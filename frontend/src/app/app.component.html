Как пользоваться системой

Для чего нужна License Management System

Система управления лицензиями ПО: вы создаёте продукты (ваши программы), типы лицензий (срок, число устройств) и клиентов (покупателей). Генерируете ключи и выдаёте их клиентам. Ваше приложение при запуске или при активации проверяет ключ через API — так вы контролируете, кто может пользоваться программой.

Зачем нужен API

API нужен, чтобы ваша программа могла проверять ключи без участия человека: приложение отправляет ключ и код продукта на сервер и получает ответ «действителен» или «истёк / не найден». Генерация ключей делается в этом веб-интерфейсе (или через API с авторизацией); проверка — из вашего кода по API.

Что такое «получить токен» (Token)

Токен — ключ доступа к API для авторизации. При входе на этот сайт токен сохраняется автоматически и подставляется в запросы. Если вы обращаетесь к API из скриптов или другого приложения — отправьте POST на /api/auth/token/ с логином и паролем, в ответ придёт токен; дальше в заголовке запросов указывайте Authorization: Token <ваш_токен>.

Как встроить проверку ключа в свою программу

Самый простой вариант — проверка только по ключу через /api/support-tickets/validate-key/. В вашем приложении при запуске/активации отправьте POST с JSON: {"key": "XXXX-XXXX-..."}. Опционально можно передать device_id и device_name для привязки к устройству. В ответе придёт, например, {"valid": true, "product": "DESKTOP-PRO"} или {"valid": false, "reason": "EXPIRED"}.

cURL пример: curl -X POST http://127.0.0.1:8000/api/support-tickets/validate-key/ -H "Content-Type: application/json" -d '{"key":"ВАШ_КЛЮЧ","device_id":"PC-1"}'

Python пример: requests.post("http://127.0.0.1:8000/api/support-tickets/validate-key/", json={"key":"ВАШ_КЛЮЧ"}).json()

JavaScript пример: fetch("http://127.0.0.1:8000/api/support-tickets/validate-key/", {method:"POST", headers:{"Content-Type":"application/json"}, body: JSON.stringify({key:"ВАШ_КЛЮЧ"})}).then(r=>r.json())

Важно: в продакшене не храните ключ «вшитым» в коде. Пользователь вводит ключ, приложение хранит его локально (например, в конфиге), и периодически валидирует на сервере.

Клиенты, продукты, типы лицензий

Клиент — тот, кому вы выдаёте лицензию (физлицо или компания). Продукт — ваше приложение (код продукта совпадает с тем, что вы передаёте при проверке). Тип лицензии задаёт срок и число устройств (пробная, подписка, бессрочная).

Что такое заказы

Заказ (Order) — запись о покупке: клиент, сумма, статус. Нужен для учёта продаж. Ключ можно генерировать без заказа или привязать к заказу (тогда видно, по какому заказу выдан ключ).

Роли и изоляция данных

Обычный пользователь видит и создаёт только своих клиентов, свои продукты и свои типы лицензий; генерирует ключи только для них. Администратор в разделе «Пользователи» видит список всех пользователей и может выбрать пользователя, чтобы просмотреть его клиентов, продукты и лицензии отдельно — данные закреплены за каждым пользователем, админ не видит «всё в одной куче», а смотрит по пользователям.

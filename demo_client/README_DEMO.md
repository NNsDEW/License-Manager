# Демонстрация работы лицензий (для комиссии)

Эта папка содержит **отдельные небольшие программы** на Python:

1. `demo_license_cli.py` — генерация + проверка (полный сценарий).
2. `demo_check_key.py` — **ТОЛЬКО проверка по ключу и БЕЗ логина/пароля**: вы вводите ключ, программа показывает сведения об этом ключе.

## Что нужно перед запуском

1. **Запустить backend** (из корня проекта, где лежит `manage.py`):

```bash
python manage.py runserver
```

2. Зайти в веб-интерфейс (Angular) и создать:
   - хотя бы **одного клиента**,
   - хотя бы **один продукт**,
   - хотя бы **один тип лицензии**.

ID этих объектов (клиента, продукта, типа лицензии) можно посмотреть в интерфейсе.

3. Убедиться, что установлен пакет `requests` (обычно уже установлен):

```bash
pip install requests
```

## Как запустить демо генерации + проверки (demo_license_cli.py)

Из корня проекта или из папки `demo_client`:

```bash
cd License Manager
python demo_client/demo_license_cli.py
```

Программа спросит:

1. Логин и пароль (например, `admin` / `admin123`).
2. `ID клиента`, `ID продукта`, `ID типа лицензии`.

Дальше она:

1. Получит токен.
2. Вызовет `/api/support-tickets/generate/` — на экране будет видно JSON с новой лицензией и ключом.
3. Вызовет `/api/support-tickets/validate-key/` — на экране будет видно, что этот ключ **валиден**.

Это наглядная демонстрация для комиссии, что:

- ключи **генерируются** на сервере,
- по тому же ключу можно **проверить** лицензию через API,
- всё работает отдельно от основного фронтенда (просто Python-скрипт).

## Как запустить простую проверку по ключу (demo_check_key.py)

Если комиссии нужно показать только, что **по введённому ключу показываются сведения**, используйте этот вариант:

```bash
cd C:\Users\namin\Desktop\zadanie
python demo_client/demo_check_key.py
```

Дальше:

1. Программа сразу будет спрашивать **только ключ** и печатать по нему:
   - действителен / недействителен,
   - продукт,
   - тип лицензии,
   - даты начала/окончания,
   - количество активаций.
